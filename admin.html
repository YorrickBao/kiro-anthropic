REQUEST PATH · 01 → 04 从候选门禁到发送前复核
  1. 过滤候选FILTER + MODEL

    排除已禁用、凭据不可用、已尝试和已确认 Depleted 的账户。关闭 Overage 的 Unknown 必须刷新 Usage 并确认 Base 余额为正；不支持目标模型则在发送前跳过。

  2. 同层选号AFFINITY / RR

    有效 x-claude-code-session-id 使用 rendezvous hash；否则按 round-robin 轮询。额度层级始终优先于会话亲和。

  3. 失败转移FAILOVER · 60S

    账户级失败会让当前账户进入 60 秒冷却并继续选号；首选账户不可用或失败后，仍可降级到 Overage。

  4. 发送前复核≤8 SENDS · ≤8 REPICKS

    发送前重查已选账户和号池：硬失效不发送；更高层就绪则重选；未发送的低层仍作后备。每个请求最多 8 次物理发送和 8 次发送前换号；达到防抖上限后，只允许仍有效的已选账户发送。

USAGE SYNC

额度校准：服务启动后立即执行，随后每 30 分钟刷新相关账户的 Usage。严格 Unknown / Depleted 使用保守探测；允许 Overage 的可路由账户使用权威观察；Depleted 只有观察到正 Base 余额才恢复。

STATIC RULE这是静态规则说明，不代表某个请求的实时选号轨迹，也不改变账号卡片展示的原始 Usage 数据。
